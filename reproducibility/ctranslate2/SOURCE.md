# CTranslate2 4.9.0 source and release audit

The GitHub release and tag resolve to commit `a22ba1c63ee35d1a0d25db149aa2a66d36a6a732`. This audit began after the protocol freeze. It follows the single-hypothesis, beam-size-one, decoder-only CPU path with no static prompt, no token suppression and no prompt echo. The measured Python boundary is the original CTranslate2 package. The ARM64 wheel's Python streaming wrapper is byte-identical to this commit's `extensions.py`. [Release](https://github.com/OpenNMT/CTranslate2/releases/tag/v4.9.0) · [Tag resolution](https://api.github.com/repos/OpenNMT/CTranslate2/git/ref/tags/v4.9.0) · [PyPI release record](https://pypi.org/pypi/ctranslate2/4.9.0/json)

## Draw, ID and probability

- The one-beam search uses `BestSampler` at top-k 1 or temperature zero and `RandomSampler` otherwise. Top-k zero keeps the full vocabulary. With one sample the CPU draws from a categorical distribution using a per-worker `std::mt19937`. A new worker or process is required for a fresh seed because `set_random_seed` changes the global seed used when the thread-local generator is first initialized. [Search selection](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L1083-L1104) · [Sampling](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/sampling.cc#L64-L123) · [CPU categorical draw](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/ops/multinomial_cpu.cc#L8-L34) · [Seed lifetime](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/random.cc#L7-L20)
- At each step the decoder computes logits and applies masks and processors. The callback and final result capture copies of the vocabulary values at this point. The engine then applies full-vocabulary log-softmax when `return_scores=True`. Random sampling restricts to top-k, scales by temperature, applies top-p if requested and normalizes for the draw. It maps a local top-k index to the original candidate index and gathers the emitted score from the input to the sampler. In the frozen stress lane the emitted score is the unscaled full-vocabulary log probability of the selected ID. The actual draw law uses the five retained scores divided by 0.7 and renormalized. [Capture and normalization](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L869-L899) · [Vocabulary copy](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L160-L173) · [Slice copies by default](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/include/ctranslate2/ops/slide.h#L8-L12) · [Score gather](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/sampling.cc#L73-L123)
- The callback's `token_id`, the final sequence's ID and the next iteration's `sample_from` share the value read from `best_ids`. Callback and final token strings are vocabulary lookups. There is no output-layer remapping in this CPU test, which uses an output size multiple of one and no restricted vocabulary. A callback-to-final ID match checks two public representations with that shared origin. Evidence from the next decoder input checks the value at its point of use. [One-step decoder call](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L859-L867) · [ID consumers](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L916-L969) · [Callback construction](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/include/ctranslate2/generation.h#L95-L115) · [Output layer](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/layers/decoder.cc#L72-L104) · [CPU size multiple](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/types.cc#L404-L430)
- The names `GenerationStepResult.logits` and `GenerationResult.logits` describe the values kept by the implementations in this lane. The callback property's public docstring and the `return_logits_vocab` parameter description instead say log probabilities. The final result property's public docstring says logits. A consumer treating either vocabulary vector as already normalized would therefore use the wrong numerical scale. The correct same-step comparison gathers `log_softmax(vector)[token_id]` against `log_prob`. This is an interface documentation discrepancy with conflicting descriptions. An empirical verdict about the selected row requires the captured outputs. [Callback and final properties](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/cpp/generation_result.cc#L14-L53) · [Parameter documentation](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/cpp/generator.cc#L264-L274)

## Public paths, EOS and forward comparison

- `generate_tokens` configures `generate_batch` with no prompt echo, one beam and an asynchronous callback. `return_log_prob` maps to `return_scores`. The wrapper calls any supplied user callback, puts the same step object on a queue and yields it. The public iterator signature provides no `return_logits_vocab` switch. Batch callbacks, queued stream rows and final IDs thus share the underlying draw implementation. The public methods offer no alternate formatter that can re-present a saved draw with new fields. Neither method exposes literal byte arrays for the emitted piece. [Stream dispatch](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/ctranslate2/extensions.py#L270-L348) · [Callback queue](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/ctranslate2/extensions.py#L473-L524) · [Python properties](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/cpp/generation_result.cc#L10-L53)
- A terminal EOS earns a callback row with a full-vocabulary vector in the vector-enabled batch lane and contributes to the aggregate score. Batch final assembly removes terminal EOS from `sequences` and `sequences_ids` by default after scoring and retains the associated vector in `GenerationResult.logits`. The stream sees the native EOS row. With the default length penalty of one, the aggregate equals the mean over all sampled scores before this stripping, including EOS. The no-penalty length setting gives the sum. A length-capped final sample also never becomes a subsequent decoder input. [EOS default and score policy](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/python/cpp/generator.cc#L186-L214) · [Default end-token resolution](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/include/ctranslate2/generation.h#L135-L161) · [EOS inclusion in search](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/include/ctranslate2/decoding.h#L139-L159) · [Score normalization](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L189-L203) · [Final assembly](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/models/language_model.cc#L240-L273)
- No-echo generation initializes iterative decoder state, prefills every prompt ID except the last and then consumes one ID at a time using the accumulated KV state. Cross-request static prompt reuse is entered only when a static prompt is given. `forward_batch` instead allocates fresh noniterative state and computes the sequence in a single call. It applies log-softmax only when requested. For sampled index `j` starting at zero, the last forward position of prompt plus the first `j` samples evaluates the conditional distribution used before sampling position `j`. The different evaluation route makes this a secondary numerical check on the realized prefix. [Native generation and cache](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/models/language_model.cc#L179-L245) · [Forward normalization](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/models/language_model.cc#L66-L101) · [Forward state](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/models/language_model.cc#L279-L299) · [KV state and decoder overloads](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/layers/transformer.cc#L568-L649)

## Post-acquisition public history

**Vocabulary-score terminology.** The public discussion of the feature explicitly established that the full vocabulary output would contain logits and that callers could compute log probabilities from them. In August 2024, PR #1755 introduced the pre-softmax copies while using log-probability wording in the option and callback docstrings. In September 2024, PR #1786 changed the final result's description to logits and retained the other two docstrings. The measured data scale agrees with the feature author's stated intent. The discrepancy is in documentation for the option and callback property. [Feature author's public clarification](https://github.com/OpenNMT/CTranslate2/issues/1616#issuecomment-2298863361) · [Original change](https://github.com/OpenNMT/CTranslate2/commit/66479457d4675fc336afe84abc2b4f024e4ca67e) · [Final property wording change](https://github.com/OpenNMT/CTranslate2/commit/6ebddf34c8d6752251c6fb8fed130942dc2c7648) · [Current public step API](https://opennmt.net/CTranslate2/python/ctranslate2.GenerationStepResult.html)

**Batch callback vector coverage.** PR #1755 made one copy of the full active batch matrix per step and moved it inside the callback loop. The first callback receives the whole matrix. Later callbacks from that same loop receive the moved-from storage. The move constructor transfers the data and resets the source. Final batch results use separately allocated per-example slices. The callback binds the batch index and token to the step result, and the API gives no special role to the first callback for reporting other examples' vectors. The source thus explains both the first callback's matrix and the later empty storage in the focused batch diagnostic. The selected `token_id` and `log_prob` use their own per-example fields. [Original change](https://github.com/OpenNMT/CTranslate2/commit/66479457d4675fc336afe84abc2b4f024e4ca67e) · [Matrix copy and slices](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L885-L899) · [Move inside callback loop](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/decoding.cc#L916-L955) · [Storage move](https://github.com/OpenNMT/CTranslate2/blob/a22ba1c63ee35d1a0d25db149aa2a66d36a6a732/src/storage_view.cc#L75-L86) · [Per-step public API](https://opennmt.net/CTranslate2/python/ctranslate2.GenerationStepResult.html)

On 2026-11-19, the GitHub issue and PR search returned eight hits for `return_logits_vocab`, zero for `GenerationStepResult logits` and one unrelated hit for `logits callback batch`. The relevant open PRs #2018, #2020 and #2025 address final beam-search logits indexing, nesting or accumulation. The report of repeated moves in #1616 also concerns the final beam-search result. The Whisper reports #1779, #1822 and #1855 concern final Whisper results. PR #1846 merged a fix to expose the Whisper final return value. The search found no report or proposed fix matching the beam-size-one multi-example callback behavior above. The actual implementation and docstrings were still present at the checked `master` commit `26e31a43b86872c16b9c66eb2468febced186f11`. Its decoder and both Python binding files were byte-identical to the pinned release.
