# TokenReceipt

[When a Language Model Server Reports a Different Token](paper/preprint/tokenreceipt.pdf) · Yufeiyang Chen

A language model samples one token, but the inference server can attach a different token and probability to it in the API response. TokenReceipt tests sampled-token attribution on the same sampling event, formalizes five serving-boundary contract invariants (`I1`–`I5`), traces downstream failures into confidence routing, LLM-as-a-Judge scoring, answer selection, and policy updates, and provides a full-transport patch and cross-engine auditing tools.

On 64 IFEval prompts, MLX-LM 0.32.2 reported a different token at 528 of 1,488 positions and a different score at 521 (`I1`/`I2` failures). In the preprint's live audits on `SmolLM2-135M` and `Qwen2.5-3B-Instruct-4bit`, the 11-check patch reduced stock attribution errors (`13/64` and `4/64` at width 5; `20/64` and `6/64` at width 1) to `0/64` while keeping non-logprob fields intact. The repository now ships a 15-check revision that also repairs streaming: in a separate November 24 audit on `SmolLM2-135M`, `Qwen2.5-3B` and `Qwen2.5-7B-Instruct-4bit`, stock streaming omitted every logprob row (`I5`, `64/64` per model and width), and the revision passed `I1`, `I2`, `I3` and `I5` at all `384` patched positions with unchanged generated text. Unified contract checks further separate row omissions in `llama.cpp` (`3/280`), non-streaming `U+FFFD` UTF-8 damage in `mistral.rs` (`708` FLORES-200 positions affecting `359` characters across `72/84` non-English pairs), and equal/unequal-length cross-row batch callback leakage in `CTranslate2` 4.9.0 (`24/24` equal-length item-0 `2V` leaks and item-1 `NULL` errors, repaired `48/48` by batch splitting).

Downstream on `Qwen2.5-3B-Instruct-4bit` (`ARC-Challenge`, confirmation $N=250$), reported-score inflation (`+0.1943` nats mean bias, propagated identically through `Inspect AI 0.3.277`) lowered aggregate ECE (`0.1250 -> 0.0318`) yet flipped `117/250` selective-routing decisions at the pilot threshold ($\tau_{85}=0.666$) and nearly tripled wrong-answer false acceptances from `27.1%` (`16/59`) to `76.3%` (`45/59`, $p<10^{-6}$). In `DeepEval 4.3.4` (`GEval.measure`, $N=94$ valid `Qwen2.5-3B` cases), missing score tokens bypassed candidate probability weighting and flipped `6/94` (`6.4%`) pass/fail decisions. On `ARC-Easy` ($N=2,108$), reported scores changed the winning answer text on `846` questions; on `SST-2`, training an online residual policy across `128` seeds lost `1.90` percentage points (`[-2.66, -1.16]`).
